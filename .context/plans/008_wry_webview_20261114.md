# 008 Opt-in GPUI WebView - 2026-11-14

- 状态: 已完成
- 任务: `.context/tasks/008_wry_webview_20261114.md`

## 目标与边界

- 独立 `liora-webview` crate，WRY 子视图由真实 GPUI `Entity<WebView>` 控件承载；仅由下游显式依赖，默认 SDK / 原生组件 / Gallery / Docs 不依赖 WRY。
- 先在隔离 X11/XWayland 会话验证 GPUI 父窗口、GTK 事件推进和子视图销毁，再开放导航、页面事件、受限 IPC 与权限策略。
- Linux GPUI 目前仅导出 XCB 窗口句柄，WRY 0.57.2 X11 路径只接受 Xlib XID；仅适配同一 X11 窗口 ID，不支持 GPUI Wayland 句柄。macOS/Windows 用 WRY 子视图 API，但本机不可验证其运行行为。
- 宿主明确处理页面消息；不把 IPC URL 视为 iframe 可信来源；默认拒绝页面权限、下载和新窗口。页面加载完成不等于成功。系统 WebKitGTK/WKWebView/WebView2 能力决定兼容性。

## 改动范围

- `Cargo.toml` workspace 仅加成员；`crates/liora-webview/{Cargo.toml,src/lib.rs,examples/native_smoke.rs,README.md}`；根 README 和稳定上下文中必要的边界说明。无 `liora` facade re-export，不改原生控件。
- `cargo check -p liora-webview --all-targets`、`cargo test -p liora-webview`、隔离 X11 原生 smoke、CTX validate；不重跑 007 原生控件复验。

## 阶段与门槛

1. 最小 GPUI 子视图 + GTK pump + 销毁：隔离 X11 窗口加载本地页面，确认 JS 回调和窗口关闭销毁，不通过则暂停后续功能。
2. 导航、显式关闭/重建、页面消息与宿主策略；权限和下载/新窗口默认拒绝。
3. 聚焦验证、使用说明和平台限制。非目标：网页兼容性承诺、Wayland 原生嵌入、任意网页的特权 JS API、浏览器替代品。
